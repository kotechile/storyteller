# prompts/brag

The `/brag` creative system, adapted from the upstream skill
([latent-spaces/brag](https://github.com/latent-spaces/brag)) for this Remotion pipeline.

## Why this directory exists

Upstream `/brag` targets **Hyperframes**: it inspects a project directory, writes `brag-plan.md`,
and hands a brief to the Hyperframes CLI. This pipeline targets **Remotion** and takes a **URL**,
not a directory. What transfers is the creative system — the rubric, the tone presets, the creative
laws, the reading floors — so that is what was ported, as version-controlled data sitting next to
the code that consumes it.

What changed in the port:

| Upstream | Here |
|---|---|
| Reads the project directory (`index.html`, CSS, routes) | Evidence is gathered in code from a URL: `src/lib/ingest.ts`, `src/lib/siteIdentity.ts`, `src/lib/siteCapture.ts` |
| Hands a brief to Hyperframes | Emits typed JSON compiled by `src/lib/bragStoryboard.ts` into the repo's `StoryboardManifest`, rendered by `src/components/../compositions/brag/BragPromo` |
| `brag-output/` directory | `runs/<timestamp>/` |
| Promote a thing you built | **Promote *and* explain** — `keyConcepts` is a mandatory field and code-enforced |
| Voice narration opt-in | Unchanged (`OMNICAST_VOICE=1`) |
| Music/SFX bundled in the skill's `assets/` | Synced into `public/brag/` by `scripts/sync-brag-assets.mjs` (Remotion can only serve files under `public/`) |

## Files

| File | Role |
|---|---|
| `creative-laws.md` | The non-negotiables, including the public-safety rule (nothing secret on screen) |
| `tones.md` | The seven tone presets and their pacing/typography/transition personality |
| `plan.md` | The 9-question rubric, the evidence contract, and the exact output JSON schema |
| `youtube-metadata.md` | Title/description/tag rules for publishing — **added in Phase 7** (not yet present) |

## Model

Prompts are consumed by **Claude via kie.ai** (`src/lib/kieClaude.ts`), configured by
`OMNICAST_BRAG_MODEL` (default `claude-opus-5-5`) and overridable per task in Supabase via
`llm_models.used_for = 'brag_planning'`.

Endpoint and verified behaviour (2026-10-11):

```
POST https://api.kie.ai/claude/v1/messages
  Authorization: Bearer <key>   (x-api-key: Bearer <key> also accepted)
  { model, max_tokens, messages:[{role, content}] }
→ { role, content:[{type:'text', text}], model, usage, stop_reason, credits_consumed }
```

Two traps, both handled in `kieClaude.ts`:

1. **Failures return HTTP 200** with `{"code":500,"msg":"The page does not exist"}` (that is what an
   unknown model alias looks like). Success is decided by response *shape*, never by `res.ok`.
2. **`claude-opus-5-5` is slow to warm**: ~92 s cold, ~9 s warm. Timeout defaults to 240 s.

Reproduce with `npx tsx scripts/probe-kie-claude.ts` and `scripts/probe-kie-claude-paths.ts`.

## Asset licensing

Bundled audio comes from the upstream skill and is **third-party**:

- Music — [ende.app](https://ende.app/en) "Happy Beats / Business Moves" (vols 1–12)
- Sound effects — [Kenney](https://kenney.nl/)

These are fine for local/personal use. Before publishing commercially, confirm the licences or swap
in licensed tracks by editing `public/brag/brag-assets.json` (generated by the sync script) and
re-running the sync. Publishing a video containing third-party audio is a real-world risk worth one
minute of thought — see the plan's risk table.

## Beat/cue data

Bundled tracks ship precomputed cue presets
(`assets/music/cues/happy-beats-business-moves-vol-N-*.music-cues.json`) giving tempo and cue
timestamps. `src/lib/beatSync.ts` reads them so sequential reveals can snap to the grid. A track
without cues falls back to a declared even grid and logs that it did so.
